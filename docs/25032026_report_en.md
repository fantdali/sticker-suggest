# Midterm Assessment Report

## Project: Intelligent Sticker and Postcard Selection System

## 1. Introduction

The goal of the project is to develop a system that selects relevant stickers from a database based on a text query. The system must consider not only the query text but also the visual semantics of the images, as well as embedded text within the images themselves. The full project also includes the generation of a new sticker if the database contains no suitable results.

This task relates to multimodal search, as it requires matching the user's text query with the visual content of the images, and in some cases, with the text within the images. This is especially important for stickers containing short inscriptions like "hello," "good morning," "happy birthday," etc.

Current system requirements:

- Support for searching by text description;
- Consideration of the visual content of the image;
- Consideration of embedded text in images;
- Scalability to a dataset of 10,000 images or more;
- Possibility of further expansion to generative mode.

Limitations:

- Searching an open dataset of stickers with annotations and text descriptions;
- Images contain noise, duplicates, and various file formats;
- Some objects are represented as GIF/WEBM, which complicates processing;
- Embedded text is often formatted with decorative fonts, making classic OCR unstable;

---

## 2. Problem Statement and Usage Scenario

The user enters a text query, for example:
"stitch",
"hello sticker",
"good morning",
"cat says hi".

The system must:

1. Convert the query to a vector representation;
2. Find the most relevant images in the database;
3. Consider both the visual content of the image and the embedded text;
4. Return the top-k most relevant results.

In its final form, the system should be able to switch to new sticker generation mode if relevant images are missing from the database or have too low a speed.

---

## 3. Dataset Description

The open [`metchee/u-sticker`](https://huggingface.co/datasets/metchee/u-sticker) sticker dataset was used as the basis for this dataset.

### Data Structure

There is a good paper analyzing the data in this dataset: https://arxiv.org/pdf/2502.19108.

The dataset contains:

- PNG, WEBM, and GIF images;
- Images with transparent backgrounds;
- Images with and without text;
- Various visual styles: characters, meme stickers, etc.;
- The context of the dialogues in which these stickers are used for some of the data.

### Limitations

1. **Duplicates**
   The dataset contains identical images with different names or IDs. This degrades search quality, as the same object can appear in the top-k list multiple times.

2. **GIF/WEBM Files**
   During OCR processing, GIF files resulted in a sharp increase in memory consumption because they contain multiple frames. For correct operation, OCR only used the first frame. WEBM files were discarded, as their processing requires a more complex pipeline.

3. **Embedded Text**
   A significant portion of the images contain text. This is important for phrase search scenarios.

4. **Stylistically Complex Text**
   The text is often written in decorative fonts, various shapes, etc. This complicates OCR.

5. **Size**
   The dataset contains 370,000 stickers, 100,000 of which are unique. Given limited resources and time, I decided to work with a subset of the recommended 10,000 images, selected randomly.

## 4. Preliminary Data Analysis

### 4.1. Review and Visual Inspection

A manual visual inspection of sample images from the dataset was performed. Data formats. Presence of text.

### 4.2. Presence of Text

An OCR approach was tested to assess the presence of text. Tesseract was initially used, but it showed poor quality on stylized text. EasyOCR was then tested, which proved significantly better on cartoon captions. I settled on EasyOCR.

### 4.3. OCR Quality

- A text OCR signal is most useful for queries with an explicit text component;
- Text may be recognized with errors or even when it is absent. Some text was recognized in 40% of the 1k images. Histograms of the average text length distribution were constructed;
- OCR confidence can serve as a useful feature for weighting the OCR signal. Histograms of the confidence distribution were constructed. Examples of images with high and low confidence were generated.

### 4.4. Duplicates

Removed duplicates using perceptual hashing to improve the diversity of the top-k results. A total of about 1.5k duplicates were removed from the 10k results.

### Conclusions

1. The database is suitable for the task of searching for stickers by description.
2. Embedded text is common enough to be taken into account in the system.
3. A multimodal approach is needed: OCR alone is not sufficient, and image embeddings alone are also insufficient.
4. A data cleaning step is necessary.

## 5. Formation of Features

Two types of features were selected: vis, and text.

### 5.1. Visual Features

The multimodal CLIP model was chosen for visual feature extraction. It maps images and text into a common embedding space, allowing direct comparison of the text query and image.

Why CLIP is suitable for this task:

- Allows image-text retrieval without separate training at the first stage;
- Convenient for rapid prototyping of semantic search;

In this work, we used image embeddings for each image in the database and text embedding for the user query. Both embeddings were obtained via CLIP.

### 5.2. Text Features from Images

Since some stickers and postcards contain embedded text, OCR was used as the second feature type.

Pipeline:

1. The image is fed to the OCR model;
2. A string of text is extracted from the image;
3. A text embedding is constructed for this string using the same CLIP text encoder;
4. This embedding is used as an additional signal source during search;
5. OCR confidence is additionally used to weight this signal.

Why is this important:

- improves search for queries with specific words;

## 6. Rationale for the chosen approach

At this stage, a retrieval approach based on semantic embeddings has been selected.

### General idea

1. A visual embedding is calculated for each image.
2. An OCR text embedding is also calculated.
3. The user query is encoded using the text encoder.
4. Search is performed based on similarity between the query and database objects.
5. The final score is constructed as a combination of the visual score and the OCR score.

### Why this approach is suitable

- directly corresponds to the problem statement of semantic search in an image database;
- easily scales to tens of thousands of images;
- does not require training the model from scratch;
- well supports the subsequent transition to vector database search.

### Why not keyword search

Searching only by OCR text is not suitable because:

- many images do not contain text at all;
- OCR can be incorrect;
- users often search for meaning or visual style rather than words.

### Why not just image embeddings

Searching only by visual embeddings is also insufficient because:

- text within images is a significant part of the semantics;
- queries like "hello sticker" or "happy birthday card" require consideration of the text itself, not just the visual style.

### Fusion Scheme

At the current stage, late fusion is used:

- similarity between query and image embedding;
- similarity between the query and OCR text embedding;
- both scores are normalized for comparability;
- the OCR score is additionally weighted by confidence.

## 7. Quality Metrics

A full quantitative assessment was not performed for the first stage. Qualitative experiments were conducted, including a visual inspection of the top-k results for several queries. After these experiments, the influence of duplicates was detected and corrected; normalization of the two scores was introduced; and the impact of OCR confidence and the weight for the OCR score was assessed.

For the final stage, it would be a good idea to implement a formal evaluation. To do this, you can select a subsample of the original dataset and collect a small set of text queries to obtain the expected relevant stickers. Manually annotate the relevance of the top-k results for each query. Based on this annotation, the following metrics can be calculated: Recall@K, HitRate@K, MRR.

### Why these metrics?

These metrics are suitable for retrieval tasks where the following are important:

- presence of a relevant object in the top-k;
- position of the first good result;
